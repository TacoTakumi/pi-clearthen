Design as built (D-06 superseded D-05 today):

- Five command forms parsed in src/args.ts; frontmatter in src/config.ts;
  steer text and the system-prompt preamble in src/steer.ts; per-hop state
  machine in src/hop-state.ts; wiring in src/index.ts.
- The clear is IN PLACE: the handler waits for idle, navigates the session
  tree to the root user message with summarize off (empty conversation, same
  session file, old hop stays as a sibling branch under /tree), clears the
  editor, resets hop state, sets the footer, sends the prompt. No newSession,
  no parentSession chain, no module state carried across instances.
- Guards added today: below-baseline (first turn already past the boundary
  warns and disarms, REQ-28); stale default doc refuses the prompt form
  (REQ-29); armed sessions get a handoff-mode block in the system prompt
  via before_agent_start (REQ-27).
- Fallback ladder: abort in turn_end, identical re-prompt from agent_settled,
  capped at two, then one warning. Turns while the agent's clear is queued
  never count (REQ-36, T-20).

## What the live runs taught

- With the user's full extension set the baseline context is about 22k
  tokens (system prompt plus tools). Boundaries must sit above that. 20000
  looped; 40000 was never reached by a small game (23.7k total).
- The replacement-session design failed live: eight steers and eight
  clearthen tool calls landed in ONE session file, no new session opened,
  context grew 22k to 34k. Root cause found later (see T-18 probe 2): the
  ladder's abort killed the pending clear. The user chose the in-place design
  before that was known; it stands on its own merits (one file per run).
- Tool dispatch needs expandPromptTemplates: true, otherwise the literal
  /clearthen text reaches the model and it loops calling the tool.
- Event contexts have no waitForIdle; agent_settled is the idle signal.
- Notifications (warnings) are not persisted in session files; only the
  transcript is evidence.

## T-18 probe (in-place hop, minimal extensions)

Done, T-18 closed. Three probes in a scratch cwd with `pi -ne -e src/index.ts`
and the local Qwen3.8-27B model:

1. Boundary 2400: steer fired; the agent wrote the doc but printed the slash
   command as text. Fixed by T-19 (steer and preamble name the tool call).
   Typing the command by hand produced the in-place hop: same file, new
   branch beside the original goal, context 3649 -> 2714.
2. Boundary 3200 after T-19: the hop only happened on the third tool call.
   Cause: pi executes the tool's queued command at once and the handler waits
   for idle; the write, tool-call and closing turns counted as three ignored
   turns, the ladder aborted the run, and the abort killed the pending clear.
   This is also what the user's 20000 run showed (eight steers, one file).
   ctx.hasPendingMessages() does not cover it. Fixed by T-20: the tool sets
   clearQueued, turn_end passes pending to the state machine, setArmed and
   agent_settled clear it.
3. Boundary 3200 after T-20: three consecutive hops in one session file, each
   on the first tool call, context 4.9k -> 2.9k per hop, steers saying hop 1,
   2, 3, footer re-armed each time.

## Gotchas

- Do not edit plan.md or spec.md by hand; use the specflo CLI.
- Never put REQ-, T-, D-, M- codes in code, tests or commit messages.
- pi caches the extension module per process: restart pi to load new code,
  /new is not enough.
- Scratch harnesses live in the session scratchpad (hooks.mjs resolver maps
  the pi package and typebox to the global install); they are not shipped.
- The user's global pi settings have compaction disabled; probe cwds used a
  project .pi/settings.json with a huge reserveTokens to force compaction.
- The permission classifier is not loaded in probes (-ne); the user's real
  runs have it.
