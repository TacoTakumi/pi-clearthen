
## Self clearing handoff

Much like /specflo-continue auto in pi and /clearthen existing behaviour this is a new long context execution system.

The extension watches the agent's context size and when it passes a boundary the agent writes a custom handoff document in docs/ or docs/projects/ and runs /clearthen docs/<handoff_file>.md. The context gets cleared and the agent is re-prompted with the handoff document. I don't know if the skill part to writing the handoff is in actual /clearthen or a separate skill like /clearthen-handoff so one would be a saver and the other a loader.

The handoff document has to contain everything the agent needs to complete the project going forward with the scope of the desired end result, what its building so it knows when to stop - it needs some kind of goal.

The context size setting should be lower than the context limit so the agent has room to write the handoff doc.

The handoff doc could have yaml frontmatter that includes the context setting. The setting is the actual context size, not a percent like specflo uses.

The footer should display that the extension mode is active and what the context setting is.

SHould there be more yaml frontmatter items?

In case the agent is in a long running task and won't settle we should take measures to intervene like specflo-continue auto does. CHeck on that, I don't think it only sends steering.

When the agent uses the /clearthen command with the md file argument the extension arms the boundary based on what was configured in the yaml frontmatter. Keeping the config there makes the skill less intrusive and more portable.

### Example usage

People test LLMs by giving them a big prompt to one-shot a video game and it works for hours to produce the result. The agent will keep on going until it's finished and end up with a very long context.

It could either be /clearthen-handoff 150000 <the long prompt all right here> or /clearthen-handoff docs/<initial_prompt_with_yaml_config>.md or /clearthen-handoff <context limit> <initial_prompt_may_have_yaml_or_not>.md

The prompt could be: Create a memory card game where the player matches magical creatures. Add a timer, combo rewards, three difficulty levels, and a final score screen.
